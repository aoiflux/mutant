# Evidence for case QUILLDROP

The workshop investigates **synthetic** evidence generated by
[`fsagen`](https://github.com/aoiflux/fsagen). Nothing here is real, nothing is
malicious, and the whole corpus comes back from a seed.

> **Status: the playbook in this directory is a draft and predates fsagen
> v0.1.0.** It was written against an earlier schema, before fsagen's format
> phase changed what `content_len` means. Regenerate it against the shipped
> schema — `fsagen --generate-schema .` then `fsagen --validate` — before you
> run the workshop. The contract below is the specification it has to satisfy.

## Why synthesized evidence

1. **It is legal and shareable.** Real triage collections carry real user data.
2. **It fits on a USB stick.** A disk image does not — and fsagen does not make
   one. It writes files into a directory on a live filesystem, which is why
   nothing in this workshop asks for an `$MFT`, a partition table or file slack.
3. **It comes back.** `--seed 88412` produces the same bytes on every laptop.

## Build it

```
fsagen --seed 88412 \
       --playbook examples/workshop/evidence/quilldrop.playbook.yaml \
       --timeline examples/workshop/case_quilldrop.body \
       --timeline-format bodyfile --timeline-source modelled \
       examples/workshop/case
```

or run `build_evidence.ps1` (Windows) / `build_evidence.sh` (Linux/macOS),
which does the same and prints what it produced.

`--timeline-source modelled` is not optional. The `observed` timeline reports
inode numbers and whatever else touched the tree, so it is reproducible only on
one machine — and it omits deleted objects, which beat 6 depends on.

## What the steps expect to find

Paths are relative to `examples/workshop/case/`. Change one and you break a
step.

| Path | What it has to be | Read by |
|---|---|---|
| `Finance/*.xlsx` (≥3) | high-entropy content, so `fs_entropy` reads above 7.9 | 1 |
| `Users/r.mehta/Inbox/invoice.eml` | real RFC 5322, one http(s) link, one attachment named `Invoice_MRD-88412.pdf.exe` | 2 |
| `Users/r.mehta/Downloads/Invoice_MRD-88412.pdf.exe` | a PE, plus a Mark-of-the-Web whose `HostUrl` host equals the email link's host | 3 |
| `Users/r.mehta/AppData/Local/Google/Chrome/History` | Chrome history containing that same URL | 3 |
| `Users/r.mehta/AppData/Roaming/MeridianSync/updater.exe` | a PE with `TimeDateStamp` zero and at least two imported DLLs | 4, 9 |
| `Users/r.mehta/AppData/Local/Temp/bkp_20260311.zip` | ≥12 members whose dates predate the archive; then backdated so `mtime` lands in 2024 while `crtime` stays at its true 2026 value | 6, 7, 9 |
| `Users/r.mehta/AppData/Local/Temp/staging/…` | deleted — present in the modelled bodyfile, absent on disk | 6 |
| `Users/r.mehta/AppData/Roaming/persistence.reg` | a `.reg` text export writing a Run key naming `updater.exe` | 1 |

Two rules on the bodyfile:

- The `name` column is **relative to the corpus root, with forward slashes**.
  Absolute paths break `fs_exists` in step 6 and are not portable.
- The modelled timeline must carry the deleted staging paths.

## Two environment hazards, both real

- **Windows Defender refuses generated PE files.** fsagen's own acceptance test
  records it flagging a generated implant as `Trojan:Win32/Bearfoos.B!ml`, and
  its verdict is not stable — it allowed and then refused identical bytes
  minutes apart. This is why the implant is `updater.exe` and not `svchost.exe`.
  Add a Defender exclusion for the output folder before the workshop.
- **Windows Search rewrites `.eml` files.** In an indexed folder it attaches an
  `OECustomProperty` stream within seconds. Generate outside indexed locations.

Mark-of-the-Web, the alternate data stream, `crtime` and `ctime` are Windows +
NTFS only. On ext4 or APFS the corpus still builds; beat 3's ADS line reports
nothing, which is the honest answer, and the other nine steps are unaffected.

## What is reproducible, and what is not

The corpus is byte-identical across machines for one fsagen version, one seed
and one playbook. So are the three exhibit digests step 9 prints.

The **manifest** step 9 writes is not, and must not be. It records when the case
was opened, when each exhibit was registered, how long the examination took and
when the seal was signed. Two examinations are two events. A tool that gave you
one number for both the evidence and the custody would be lying about one of
them — and which one it lies about is the thing you would be cross-examined on.
